## 1. 问题根源（已读代码确认）

现有导入（`parsePRD`）是**规则驱动**：

- 标题（`#`/`##`）按关键词表 `headingToId` 映射到框架节（目的/范围/定义/…）；
- **文档有、框架没有的标题**（`new::xxx`）内容会整段进入「其他」兜底节；
- 标题用词与框架不一致（如文档写"产品概述"、框架叫"产品信息与目标"）→ 映射不到 → 进「其他」；
- `parseAutoGen` 按文档标题直接建框架，可能误判/漏分。

结果：内容错位、必填节空、兜底节臃肿——这正是用户痛点。

## 2. 功能设计：AI 结构对齐

### 2.1 一句话

**AI 把"内容块"从错误的节搬到正确的节，逐条确认后写入，生成可回滚的结构对齐版本。**

### 2.2 自动操作（AI 直接提议，人确认后执行）

复用 v17.1 的块级机器，支持两种移动：

| 操作 | 说明 | 数据形状 |
|---|---|---|
| `moveBlock` | 把 text 节里的一个块（段落/列表/表格/标题）搬到目标节 | `{fromSection, match(块原文), toSection, position: after\|before\|start\|end, anchor(目标锚点块原文)}` |
| `moveRow` | 把 table 节的一行搬到目标表格（列数必须一致） | `{fromSection, match(首列文本), toSection, position, anchor(目标行首列文本)}` |

### 2.3 建议类（只给文字，人工执行，避免自动改框架）

- `renameSection`：建议把某节标题改成更贴切的名称（改标题会影响规则定位，交给人工在框架编辑器改）；
- `mergeSections` / `splitSection`：合并/拆分建议（可用多次 moveBlock 等价完成，AI 只提示）；
- `deleteEmpty`：某节空且非必填，建议删除或合并。

> 自动只做"搬内容"，框架结构（增删节/改名）一律人工决定——与"先闭环后扩展"一致。

### 2.4 错位检测（确定性信号，不进 LLM）

`aiAlignHint()` 本地计算：

- 兜底节（其他/附录）纯文本占比（>25% → 高风险）；
- 必填节为空但全文内容充足（疑似内容没归位）；
- 单节块数异常（某节 8+ 块而多处空节 → 疑似合并错位）。

返回 `{level: 'high'|'mid'|'low', reasons[]}`；导入后与 AI 面板内显示提示。

### 2.5 流程

```
入口：AI 面板「AI 结构对齐」按钮（导入后检测到错位时 toast 提示引导）
  → aiAlign()：框架+逐节文本（含兜底节）给 AI
  → AI 返回 {moves:[moveBlock/moveRow], suggestions:[…], summary}
  → 本地校验 aiValidateMove()（来源存在/目标存在/锚点匹配/表格列数一致/不搬回原节）
  → 生成 pendingAlign 待确认列表（复用 Diff 交互：接受/拒绝/暂缓/全部接受）
  → 确认后执行跨节移动 → 生成「结构对齐」版本（双节补丁，可回滚）
```

### 2.6 版本与恢复

- 新版本 `kind:'ai'`、`label:'结构对齐'`；
- 一次移动产生**两个补丁条目**：来源节 `{kind:'block', blockOld, blockNew:'', anchor}`（删除）+ 目标节 `{kind:'block', blockOld:'', blockNew, anchor}`（插入）；
- 现有 `aiReverseEntries/aiEnsureTarget` 已支持这两种条目的反向恢复（删除反向=按锚点插回，插入反向=移除）——**恢复逻辑零新增**，直接复用；
- 表格行移动同理（`rowOp:'delete'` + `rowOp:'insert'`）。

### 2.7 数据模型

```js
p.ai.pendingAlign = {
  id, createdAt, summary,
  items: [{
    id, kind:'moveBlock'|'moveRow'|'suggestion',
    fromSection, fromTitle, toSection, toTitle,
    match, position, anchor,
    blockOld, blockNew,          // moveBlock 预览/执行用
    rowOld, rowNew,              // moveRow 预览/执行用
    suggestion,                  // suggestion 类
    validation:{ok,warnings[],blocked[]},
    status:'pending'|'accepted'|'rejected'|'deferred'
  }]
}
```

### 2.8 UI

- AI 面板新增「AI 结构对齐」按钮（与深度体检/一键优化并列）；
- 面板新增「结构对齐建议」区：每条显示 `来源节 → 目标节` 预览 + 校验徽标，接受/拒绝/暂缓/全部接受；
- 建议类条目以文字卡展示（人工执行）；
- 导入完成后（包装 `doImportText`）检测到高风险错位 → toast「检测到内容与框架可能错位，可到 AI 助手执行『结构对齐』」。

## 4. 验收要点

1. 构造错位样例（正文在「其他」、必填节空）→ 提示高风险；
2. AI 提议 moveBlock/moveRow → 校验通过 → 确认后内容真的搬过去；
3. 表格行移动列数不一致 → blocked 禁接受；
4. 搬移后生成「结构对齐」版本 → 恢复后内容回到原位；
5. 建议类（改名/合并）只显示文字，不自动执行；
6. 导入触发提示但不自动跑 AI（人工点按钮）。

## 7. v17.3 变更记录（用户反馈三项）

1. **停止 AI**：`aiGlobalAbort`（AbortController）+ `aiCancelFlag` 全局中止，面板运行中显示「■ 停止」，中断不写入、可重试；公开 `__AICtrl.stop`。
2. **导入默认自动框架**：`doImportText` 包装器在无项目/空项目时改走 `createProject` + `autoGenImport`（按文档标题建 `agN` 框架），不再硬套 14 节；有内容项目保持原确认流程。
3. **对齐自动调整（非仅建议）**：改名/删空节/合并/拆分由 AI `ops` 真正执行：
   - rename：改框架节标题（`fwname` 补丁，可还原）；
   - deleteEmpty：仅空且非必填节可删（`fwdel` 补丁，可还原）；
   - merge：整节块/行并入目标节后删除来源节（双节补丁 + `fwdel`）；
   - split：从 text 节拆块到新节（`fwadd` + 双节补丁，可还原）；
   - 框架级还原统一走 `aiReverseVersionPatch`（框架条目先行 + 节条目），含框架条目的恢复不生成「恢复前快照」。

## 8. v17.4 变更记录（导入目录/标题精准识别）

真实案例：贷款需求文档导入识别出 290 个框架节（实际只有 50 个真实标题）。根因在 block1：

- `headingLevelOf` 的 `/[a-z]/i` 兜底把 Word 自动目录样式（TOC1-TOC4）全部当二级标题；outlineLvl=9（正文）也当标题；加粗兜底把封面日期行当标题。
- `parseAutoGen` 把目录条目（含页码）与正文编号行当标题。

修复：headingLevelOf 移除过宽兜底、显式排除目录样式、outlineLvl 只认 0-8、加粗兜底排除封面行；parseAutoGen 跳过「目录」块、有 `#` 标题时禁用编号行兜底。真实文件验证 **290 → 72 节**；6 套回归 142 断言全绿。

## 19. v17.15 变更记录（AI 撰写草稿：从产品描述生成整份 PRD）
